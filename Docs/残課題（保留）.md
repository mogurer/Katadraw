## 1. 円ステージ「1点だけ伸ばす」問題【解決済み】

### 現象
1点だけガイド円上に伸ばすと、他が崩れていても実現率が高くなる。

### 試したこと
- **案F**: 誤差を「平均 + 最大」の複合スコアにする
  - `USE_COMBINED_ARC_ERROR := true`
  - `ARC_ERROR_AVG_WEIGHT := 0.7`、`ARC_ERROR_MAX_WEIGHT := 0.3`
- **結果**: 挙動はあまり変わらず。根が深そうな問題のため保留。

### 現状の仕様に戻す方法
`scripts/stage_manager.gd` の定数を変更：

```gdscript
const USE_COMBINED_ARC_ERROR := false  # true → false で平均のみの評価に戻る
```

### 関連コード
- `scripts/stage_manager.gd`: `_calc_unified_arc_metrics` 内の案F分岐

## 2. ねこの顔ステージの評価【解決済み】

### 現象
- 右耳・頭頂で実現率がズレる
- ポイントを外側へ動かすと実現率が上がる（本来は下がるべき）
- 打点分布によって実現率が変わる（見た目が同じでも）

### 試したこと
- 点対応評価、ref_r_avg、幾何平均など → 直感と合わず
- **対応**: 輪郭ベースの評価を維持しつつ、スケールに ref_r_max を使用（直観に近い評価を優先）
- 外側へのはみ出しで実現率が上がるケースは稀なエッジケースとして許容

### 関連ドキュメント
- `Docs/評価ロジックの現状.md`

## 4. ステージ管理の統一【保留】

今後、ステージ管理の責務とデータ経路を整理する必要がある。  
優先度は 1 から順に進める。

### 1. 最終ステージ設定の生成を 1 本化する

### 現状の課題
- ステージの有効設定を作る処理が複数ある
  - `Resources/stage_config.gd`: `StageConfig.merge_config()`
  - `scripts/stage_debug_overrides.gd`: `fill_missing_from_type_defaults()`
  - `scripts/custom_stage_file.gd`: `effective_config()` / `effective_config_with_shape()`
- 同じ「欠損値を埋めてプレイ用設定を作る」処理なのに、未知 `type` の扱いなどが一致していない。

### 目標
- 「このステージの最終的な設定は何か」を作る関数を 1 本化する。

### 2. ステージ開始経路を統一する

### 現状の課題
- 通常開始、デバッグテスト開始、ルール画面デモで初期化経路が異なる。
- `scripts/game.gd` から `StageManager.start_stage()` を使う経路と、`stage_manager` の一部フィールドを直接代入する経路が混在している。

### 目標
- すべてのステージ開始を共通の初期化 API に寄せる。

### 3. ステージ関連の責務を `game.gd` から分離する

### 現状の課題
- `scripts/game.gd` がステージ開始、デバッグ UI、pending 値、再開、カスタムステージ処理などを持ちすぎている。
- `StageManager` が「管理者」になりきっておらず、状態のオーケストレーションが分散している。

### 目標
- ステージ関連の責務を `StageManager` または専用モジュールへ寄せる。

### 4. `type` / `stage_id` / index の意味を整理する

### 現状の課題
- 組み込みステージでは `type` が図形種別、カスタムステージでは ID 的な意味も混ざる。
- 本編ステージ index とデバッグ一覧 index が同一概念として扱われる箇所があり、再開やテスト時の不整合を招きやすい。

### 目標
- 図形種別、ステージ識別子、表示順 index の役割を明確に分離する。

### 5. 外部ステージデータの読込経路を統一する

### 現状の課題
- `mbus` / `mug` は `CustomStageFile` 経由で読む一方、七芒星系は `scripts/stage_manager.gd` 内で直接 JSON を読む。
- 同じ「外部 shape を持つステージ」でも、前提スキーマや読込責務が統一されていない。

### 目標
- JSON 由来ステージの読込・検証・有効設定化を同一パイプラインに寄せる。

### 関連コード
- `Resources/stage_data.gd`
- `Resources/stage_config.gd`
- `scripts/stage_manager.gd`
- `scripts/stage_debug_overrides.gd`
- `scripts/custom_stage_file.gd`
- `scripts/game.gd`
